# 카카오소설 다운로더

FlaskFarm(FF)에 설치하는 카카오페이지 **소설 전용** 플러그인입니다.
작품마다 시작 회차를 선택해 오래된 회차부터 최신 회차 방향으로 처리합니다.

**v0.2.2:** 복사본 회차 번호 자릿수를 화면에서 선택할 수 있습니다. 자동 테스트 58개를 통과했으며, 2026-11-18 공개 무료 회차 한 편의 실제 본문 수신 → TXT → EPUB 저장을 확인했습니다.
카카오 로그인 계정 및 실제 FF/NAS 환경에서의 연동은 아직 검증하지 않았습니다.
카카오 웹 API가 변경되었거나 계정별 응답이 다르면 명시적인 오류로 멈춥니다.

## 설치

1. FF의 플러그인 관리에서 Git 저장소 URL로 설치합니다.
   ```text
   https://github.com/endells/kakao_novel_downloader
   ```
2. 설치 후 필요하면 FF를 재시작합니다. 메뉴에 **카카오소설 다운로더**가 표시됩니다.
3. **설정 / 스케줄**에서 **경로 선택**을 눌러 다운로드 폴더를 고른 뒤 **설정 저장**을 누릅니다.
   문피아 다운로더와 같은 FF 폴더 선택창을 사용합니다. 입력된 경로가 없으면 열 수 있는 상위 폴더에서 시작하며, 취소하면 입력값을 유지합니다. 직접 경로 입력도 가능합니다.
   FF 컨테이너 내부 저장 경로를 지정합니다.
   NAS `/volume1/books`를 컨테이너 `/downloads`에 마운트했다면 `/downloads`를 입력합니다.
   NAS 경로를 마운트 없이 그대로 입력하면 NAS의 원하는 폴더에 저장되지 않을 수 있습니다.
4. 로그인한 `page.kakao.com`에서 Cookie-Editor → Export → JSON으로 내보낸 쿠키를 입력하고 저장합니다.
5. 소설 작품 번호로 **저장된 쿠키 검증**을 실행합니다.
6. **작품 등록 / 수동**에서 작품 URL 분석 → 시작 회차 선택 → 내 작품에 저장 → 지금 실행합니다.
7. 한 작품으로 정상 동작을 확인한 뒤 자동 확인을 켭니다. 기본 점검 간격은 30분이며, 기본 자동 확인은 꺼져 있습니다.

Python 3.9 이상과 `requests`가 필요합니다. FF 환경에는 일반적으로 requests가 있습니다.
없으면 FF 컨테이너의 Python 환경에서 `python -m pip install -r requirements.txt`로 설치합니다.
플러그인 import 중 임의 패키지 설치는 하지 않습니다.

## 시작 회차와 기다무

- 시작 회차 **자체를 포함**합니다. 예: 100화 선택 → 100화 → 101화 → 102화.
- 제목에서 숫자를 추측하지 않고 전체 목록의 공식 `order_value` 오름차순으로 순서를 정합니다. 페이지 탐색용 `cursor_index`로 회차 순서를 추측하지 않습니다.
- UI의 **목록 순번**은 외전·특별편 등을 포함하므로 제목의 ‘100화’와 다를 수 있습니다.
  반드시 제목을 확인하여 선택하세요. 저장은 회차 고유 ID로 하므로 앞에 회차가 추가돼도 시작 위치가 밀리지 않습니다.
- 종료를 **최신화까지 계속**으로 두면 신규 회차도 다음 자동 점검에서 확인합니다.
- 작품마다 기다무 사용을 켜거나 끌 수 있습니다. 기다무는 작품당 실행 1회에 최대 1장입니다.
- 무료·소장·유효한 대여 회차는 현재 접근권으로 처리합니다.
- 잠금 회차에서는 기다무 충전과 해당 회차의 `RT05` 사용 가능 응답이 모두 확인될 때만 사용합니다.
- 충전 대기, 기다무 제외 또는 확인 불가능 회차에서 해당 작품은 멈춥니다. 뒤 회차로 건너뛰어 이용권을 사용하지 않습니다.
  다른 작품은 계속 처리합니다. 최신 유료 회차에 도달해도 결제하지 않습니다.
- 일반 대여권, 소장권, 캐시를 사용하는 기능은 없습니다. 기다무 제한과 대기 시간을 변경하지 않습니다.
- 본문 전송 실패 시 완료로 표시하지 않습니다. 사용한 대여권은 별도 기록을 남겨 복구에 사용합니다.
- 이용권 사용 요청 후 연결이 끊기면 **대여 결과 확인 필요**로 남깁니다.
  다음 실행에서 대여된 것이 확인되면 이어받지만, 여전히 잠금 상태면 자동 재차감하지 않습니다.
  카카오에서 대여 내역을 확인한 후 이력 화면의 **확인 후 재시도**를 사용하세요.

## 기능

| 항목 | 내용 |
|---|---|
| 작품 등록 | 작품 URL/번호 분석, 시작·종료 회차 선택, 작품별 수정 |
| 수동 실행 | 작품 하나 또는 등록 작품 전체 실행, 중지, 재시작 후 이어받기 |
| 자동 확인 | 10분~7일 간격, FF 재시작 시 스케줄 등록 |
| 중복 방지 | 작품 ID + 회차 ID, 완료 파일 SHA-256 확인 |
| 동시 실행 방지 | 스레드 및 FF 프로세스 간 파일 잠금 |
| 저장 | UTF-8 TXT, 작품별 텍스트 합본 EPUB 3, info.json |
| 이력 | 최근 300개 회차, 최근 100개 로그 표시, 최대 3,000개 로그 보관 |
| 시간 | Asia/Seoul 기준 표시 및 +09:00 저장 |
| 로그인 정보 | 별도 0600 쿠키 파일, 화면 재노출/원문 응답 로깅 없음 |

저장 예:
```text
저장폴더/작품명 [작품번호]/
  info.json
  00100_회차 제목 [회차ID].txt
  작품명.epub
```

합본 EPUB은 해당 작품의 검증된 완료 TXT 전체를 묶습니다. 시작 범위를 나중에 바꿔도 이미 받은 TXT가 합본에서 제거되지는 않습니다.
작품 등록 해제 시에도 파일과 이력은 유지합니다. 제목이 바뀌어도 기존 작품 폴더를 유지합니다.
저장 루트를 변경하면 기존 파일을 자동 이동하지 않습니다. 기존 파일이 남아 있으면 완료로 인식하며, 새 회차는 새 루트에 저장합니다.

## 시즌별 파일 복사 (v0.2.0)

**시즌별 파일 복사** 메뉴에서 원본 TXT를 유지한 채 다른 폴더로 자동 또는 수동 복사합니다. 시즌별로 규칙을 여러 개 저장할 수 있습니다. 파일 내용과 인코딩은 원본 그대로 복사하고 이름만 바꿉니다.

천재 궁수의 스트리밍 시즌 5 예시:

| 항목 | 설정 / 결과 |
|---|---|
| 작품 번호 / 시즌 | `56505778` / `5` |
| 원본 | `01500_시즌5 304화 각자의 게임(1) - 릴 [69188951].txt` (앞 번호는 설명용 예시) |
| 회차 계산 | 제목에서 인식: `304화` 사용 |
| 복사 대상 폴더 | 기존 시즌 5 폴더를 선택 (FF 컨테이너 내부 경로) |
| 추가 하위 폴더 | 기존 시즌 폴더라면 비움. 새로 나누려면 `{title}/시즌 {season}` |
| 파일명 규칙 | `{episode:05d}_{subtitle}.txt` |
| 복사본 | `00304_각자의 게임(1) - 릴.txt` |

1. **기존 원본 TXT 폴더**를 비우면 이 다운로더의 해당 작품 저장 완료 이력에서 가져옵니다. 다른 곳에서 받은 파일은 원본 폴더를 지정하세요. 그 폴더 바로 아래의 TXT만 읽고 하위 폴더는 탐색하지 않습니다.
2. **복사 대상 폴더**에 기존 시즌 5 파일들이 들어 있는 폴더를 지정합니다. 원본 폴더와 다른 폴더여야 합니다.
3. 기존 파일과 같은 자릿수·제목 배치로 파일명 규칙을 입력합니다. **복사 미리보기**의 ‘대상 폴더의 기존 파일명 보기’에서 실제 이름 최대 20개를 확인할 수 있습니다. 인식 가능한 예시가 없는 경우 기존 이름 규칙을 자동 추측하지 않습니다.
4. 제목에 시즌 회차가 있으면 **제목에서 인식**을 선택합니다. 다른 시즌이 명시된 파일은 제외합니다. 시즌 표기가 없는 파일은 지정한 시즌의 파일로 간주하므로 원본 폴더/번호 범위를 좁혀주세요.
5. 제목에 회차가 없으면 **원본 번호에 기준 번호 보정 적용**을 선택합니다. 예: 원본 번호 `1500` → 시즌 회차 `304`이면 다음 원본 `1501`은 `305`가 됩니다. 이력 사용 시 원본 번호는 현재 다운로드 목록 순번이고, 별도 폴더는 파일명 맨 앞 숫자입니다. 파일명에 공백이 있어도 처리합니다.
6. 미리보기의 원본→복사 대상과 충돌을 확인하고 **저장하고 기존 파일 복사**를 누릅니다. 복사는 백그라운드로 진행하며 중지 후 다시 실행할 수 있습니다. 이 작업은 쿠키나 네트워크를 사용하지 않습니다.
7. **이 작품 다운로드 작업이 끝날 때 자동 복사**를 켜고 규칙을 저장하면 이후 수동/예약 다운로드 작업 후 저장된 파일을 확인해 복사합니다. 다운로드 이력과 대여권에는 영향을 주지 않습니다. 별도의 실시간 폴더 감시는 아닙니다. 별도 원본 폴더를 지정한 규칙도 해당 작품 다운로드 작업 후 스캔합니다.

이름 변수: `{title}` 작품명, `{season}` 시즌, `{episode}` 시즌 회차, `{subtitle}` 시즌/회차 뒤의 제목, `{original_number}` 원본 번호, `{original_name}` 확장자 없는 원본 파일명, `{pid}` 회차 ID(별도 원본 폴더는 0). 숫자는 `{episode:03d}` 또는 `{episode:05d}`처럼 1~8자리로 지정할 수 있습니다.

기존 파일 처리:

- 같은 이름 또는 인식한 같은 회차의 파일이 있으면 내용을 비교합니다. 같은 내용이면 건너뛰고, 다른 내용이면 **충돌 / 기존 파일 보호**로 남깁니다. 자동 덮어쓰기·삭제는 없습니다.
- 같은 회차 판별은 설정한 이름 규칙, `304화` 표기, 파일명 맨 앞 숫자를 사용합니다. 인식할 수 없는 이름은 같은 파일명 충돌만 확인합니다. 여러 시즌이 섞인 대상 폴더는 시즌별로 나누어 지정하세요.
- 여러 원본이 같은 회차/이름으로 변환되면 모두 보류합니다. 미리보기와 작업 기록에서 확인하세요.
- 다운로드 이력과 원본 내용이 다르면 확인 대상으로 남깁니다. 한 번에 최대 10,000개 TXT, 미리보기는 첫 300개를 표시하고 전체 상태 건수를 함께 보여줍니다.
- 원본 TXT와 EPUB은 그대로 유지합니다. 시즌별 EPUB을 재구성하거나 삽화를 함께 복사하는 기능은 포함하지 않습니다.
- 완성된 임시 파일을 대상 폴더 안에서 하드링크로 공개하여 기존 파일을 보호합니다. 대상 파일시스템에 하드링크 지원이 필요하며 미지원 시 실패를 기록하고 원본은 유지합니다. 원본과 대상은 서로 다른 파일시스템이어도 됩니다.

## 현재 범위와 알려진 제한

- **TXT와 텍스트 EPUB** 중심입니다. 삽화는 `[삽화]` 위치 표시만 저장하고 이미지 자체는 저장하지 않습니다.
- 작품명 검색/연재 목록 탐색, 표지 수집, Telegram/Discord 알림은 이번 버전에 포함하지 않았습니다.
- 이미지 전용 또는 암호화된 소설 뷰어는 지원하지 않습니다. 지원하지 않는 형식을 억지로 변환하지 않습니다.
- 기다무 판단은 보수적으로 동작합니다. 카카오가 일반 대여권을 추천해 `RT05` 대신 다른 유형을 반환하면,
  실제로 기다무 사용이 가능한 작품이라도 **기다무 확인 필요**로 멈출 수 있습니다. 이때 비밀값 없는 응답 구조 확인이 필요합니다.
- 새 회차 삽입으로 순번이 달라져도 기존 TXT 이름을 자동 재정렬하지 않습니다. EPUB 목차는 재확인된 목록 순번을 사용합니다.
- 실제 카카오 로그인/기다무 사용/FF 스케줄 연동은 설치 후 테스트가 필요합니다. 테스트 통과는 실서비스 동작 보장을 뜻하지 않습니다.

오류 보고 시 화면에 나온 오류 코드, FF 버전, 플러그인 버전, 작품 번호만 알려주세요.
쿠키·대여 확인값·서명 URL·본문은 GitHub 이슈나 공개 로그에 올리지 마세요.

## 개발 테스트

저장소의 상위 디렉터리에서 실행:
```sh
python -m pip install -r kakao_novel_downloader/requirements-dev.txt
python -m unittest discover -s kakao_novel_downloader/tests -v
```
테스트는 모의 서버 응답과 임시 디렉터리만 사용하며 실제 계정이나 대여권을 사용하지 않습니다.
템플릿 JavaScript 문법 검사에는 Node.js가 필요합니다. FF 설치 시에는 Node.js가 필요하지 않습니다.

### v0.1.2 수정

### v0.2.1 복사 설정 안내 개선

- 회차 계산 선택지에서 특정 회차 예시를 빼고 **제목에 적힌 회차 사용**, **원본 번호를 시즌 회차로 바꾸기**로 표시합니다.
- 제목 방식은 파일마다 ‘○○화’를 읽습니다. 예를 들어 `01500_시즌5 304화 제목.txt`는 304화, 다음 파일의 제목이 305화이면 305화가 됩니다. 기준 번호 입력칸은 숨깁니다.
- 번호 보정 방식은 기준 파일 하나의 원본 번호와 시즌 회차를 짝지어 입력합니다. 원본 1500 → 시즌 304로 설정하면 1501 → 305, 1502 → 306으로 계산됩니다. 현재 입력값의 계산 예시를 화면에 표시합니다.
- 복사 범위는 **변환 전 원본 번호** 기준입니다. 예: 시작 1500 / 끝 1510, 위 번호 보정 기준이면 시즌 304~314화. 양쪽 0은 번호 제한 없음, 시작 1500 / 끝 0은 원본 1500번부터 끝까지입니다. 기준 번호 입력만으로 복사 시작 범위가 바뀌지는 않습니다.
- 원본 번호가 다운로드 이력의 목록 순번인지, 별도 원본 폴더의 파일명 맨 앞 숫자인지 현재 선택에 맞춰 안내합니다.
- 파일명 형식 선택지에는 형식 이름을 표시하고, 규칙→완성 파일명 예시는 별도 표로 제공합니다. `{episode:05d}`는 최소 5자리 표시로, 12화는 `00012`, 304화는 `00304`가 됩니다.

화면의 설명용 예시와 실제 설정값을 구분했습니다. 파일별 최종 결과는 **복사 미리보기**에서 확인하세요. 기존 복사 규칙과 파일 처리 방식은 유지됩니다.

### v0.2.2 회차 번호 자릿수 선택

시즌별 파일 복사 → **회차 번호 자릿수**에서 ‘앞에 0 붙이지 않기’ 또는 최소 1~8자리를 선택하세요. 회차 변수만 바꾸고 파일명 뒤의 작품명·제목은 유지합니다. 선택한 자릿수는 파일명 규칙에 반영되어 규칙 저장 시 함께 저장됩니다. 저장된 규칙을 다시 열거나 직접 수정해도 자릿수 선택에 반영합니다.

예: ‘회차 번호_작품명’ 형식에서 시즌 회차 304를 복사할 때:

| 자릿수 | 파일명 |
|---|---|
| 3자리 | `304_천재 궁수의 스트리밍.txt` |
| 4자리 | `0304_천재 궁수의 스트리밍.txt` |
| 5자리 | `00304_천재 궁수의 스트리밍.txt` |
| 6자리 | `000304_천재 궁수의 스트리밍.txt` |

실제 번호가 선택한 자릿수보다 길면 자르지 않습니다. 변경 후 **규칙 저장**을 눌러야 이후 자동 복사에 적용됩니다. 기존 복사본 이름은 변경하지 않으며, 기존의 동일 회차 검사 설정에 따라 건너뛰거나 충돌로 표시합니다.

### v0.2.3 실행 로그 / 스케줄 진단

**실행 로그** 탭에서 자동 확인 설정, FF 스케줄 등록 여부, 간격, 현재 작업 상태를 확인합니다. 전체 작업 또는 스케줄 기록만 선택할 수 있으며 5초마다 갱신합니다. 최근 1,000건을 표시하고 DB에는 약 3,000건을 보관합니다(한국 시각).

스케줄 등록·호출·작업 시작·작업 종료를 기록합니다. 자동 확인 꺼짐/다른 작업 진행 중으로 건너뛴 이유, 쿠키 미설정 등 시작 실패도 기록합니다. 저장한 파일이 없어도 대상 작품 수와 작품별 점검 결과(충전 대기, 최신화 완료, 오류 등)를 남깁니다. 작업 종료는 모든 작품의 성공을 의미하지 않으므로 전체 작업 로그도 확인하세요.

업데이트 후 FF를 재시작하세요. 자동 확인이 켜져 있는지 확인한 뒤 설정된 간격이 지나면 `[스케줄] 호출됨`을 확인합니다. 등록만 있고 호출이 없다면 FF 자체의 스케줄러 실행 상태를 확인해야 합니다. 기존 버전이 기록하지 않은 과거 호출은 복원되지 않습니다. 사용자 NAS에서의 실제 예약 실행은 업데이트 후 확인이 필요합니다.

### v0.2.4 서버 갱신 쿠키 자동 저장

다운로드·스케줄·작품 분석·쿠키 검증 중 서버가 보내는 Set-Cookie를 반영하여 쿠키 파일을 자동 갱신합니다. 다음 실행은 갱신된 쿠키를 사용합니다. 변경된 경우에만 0600 권한으로 원자적으로 저장하며, 실행 로그에는 저장 성공/실패만 남기고 쿠키 값은 남기지 않습니다. 만료·삭제된 쿠키와 도메인·경로·보안 속성도 반영합니다. 저장 실패 시 다음 응답 및 종료 때 재시도합니다.

서버가 갱신을 보내지 않으면 기존 쿠키를 유지합니다. 로그인 기간을 강제로 연장하거나 만료 후 자동으로 재로그인하는 기능은 아닙니다. 실제 계정의 장기 유지 여부는 NAS 실행 로그와 다음 날 인증 결과로 확인해야 합니다.
