# 카카오소설 다운로더

FlaskFarm(FF)에 설치하는 카카오페이지 **소설 전용** 플러그인입니다.
작품마다 시작 회차를 선택해 오래된 회차부터 최신 회차 방향으로 처리합니다.

**v0.1.2 — 초기 연동 버전:** 순차 처리·중복 방지·파일 저장은 모의 응답으로 테스트했습니다.
카카오 로그인 계정 및 실제 FF/NAS 환경에서의 연동은 아직 검증하지 않았습니다.
카카오 웹 API가 변경되었거나 계정별 응답이 다르면 명시적인 오류로 멈춥니다.

## 설치

1. FF의 플러그인 관리에서 Git 저장소 URL로 설치합니다.
   ```text
   https://github.com/endells/kakao_novel_downloader
   ```
2. 설치 후 필요하면 FF를 재시작합니다. 메뉴에 **카카오소설 다운로더**가 표시됩니다.
3. **설정 / 스케줄**에서 **경로 선택**을 눌러 다운로드 폴더를 고른 뒤 **설정 저장**을 누릅니다.
   문피아 다운로더와 같은 FF 폴더 선택창을 사용합니다. 입력된 경로가 없으면 열 수 있는 상위 폴더에서 시작하며, 취소하면 입력값을 유지합니다. 직접 경로 입력도 가능합니다.
   FF 컨테이너 내부 저장 경로를 지정합니다.
   NAS `/volume1/books`를 컨테이너 `/downloads`에 마운트했다면 `/downloads`를 입력합니다.
   NAS 경로를 마운트 없이 그대로 입력하면 NAS의 원하는 폴더에 저장되지 않을 수 있습니다.
4. 로그인한 `page.kakao.com`에서 Cookie-Editor → Export → JSON으로 내보낸 쿠키를 입력하고 저장합니다.
5. 소설 작품 번호로 **저장된 쿠키 검증**을 실행합니다.
6. **작품 등록 / 수동**에서 작품 URL 분석 → 시작 회차 선택 → 내 작품에 저장 → 지금 실행합니다.
7. 한 작품으로 정상 동작을 확인한 뒤 자동 확인을 켭니다. 기본 점검 간격은 30분이며, 기본 자동 확인은 꺼져 있습니다.

Python 3.9 이상과 `requests`가 필요합니다. FF 환경에는 일반적으로 requests가 있습니다.
없으면 FF 컨테이너의 Python 환경에서 `python -m pip install -r requirements.txt`로 설치합니다.
플러그인 import 중 임의 패키지 설치는 하지 않습니다.

## 시작 회차와 기다무

- 시작 회차 **자체를 포함**합니다. 예: 100화 선택 → 100화 → 101화 → 102화.
- 제목에서 숫자를 추측하지 않고 전체 목록의 `cursor_index`로 순서를 정합니다.
- UI의 **목록 순번**은 외전·특별편 등을 포함하므로 제목의 ‘100화’와 다를 수 있습니다.
  반드시 제목을 확인하여 선택하세요. 저장은 회차 고유 ID로 하므로 앞에 회차가 추가돼도 시작 위치가 밀리지 않습니다.
- 종료를 **최신화까지 계속**으로 두면 신규 회차도 다음 자동 점검에서 확인합니다.
- 작품마다 기다무 사용을 켜거나 끌 수 있습니다. 기다무는 작품당 실행 1회에 최대 1장입니다.
- 무료·소장·유효한 대여 회차는 현재 접근권으로 처리합니다.
- 잠금 회차에서는 기다무 충전과 해당 회차의 `RT05` 사용 가능 응답이 모두 확인될 때만 사용합니다.
- 충전 대기, 기다무 제외 또는 확인 불가능 회차에서 해당 작품은 멈춥니다. 뒤 회차로 건너뛰어 이용권을 사용하지 않습니다.
  다른 작품은 계속 처리합니다. 최신 유료 회차에 도달해도 결제하지 않습니다.
- 일반 대여권, 소장권, 캐시를 사용하는 기능은 없습니다. 기다무 제한과 대기 시간을 변경하지 않습니다.
- 본문 전송 실패 시 완료로 표시하지 않습니다. 사용한 대여권은 별도 기록을 남겨 복구에 사용합니다.
- 이용권 사용 요청 후 연결이 끊기면 **대여 결과 확인 필요**로 남깁니다.
  다음 실행에서 대여된 것이 확인되면 이어받지만, 여전히 잠금 상태면 자동 재차감하지 않습니다.
  카카오에서 대여 내역을 확인한 후 이력 화면의 **확인 후 재시도**를 사용하세요.

## 기능

| 항목 | 내용 |
|---|---|
| 작품 등록 | 작품 URL/번호 분석, 시작·종료 회차 선택, 작품별 수정 |
| 수동 실행 | 작품 하나 또는 등록 작품 전체 실행, 중지, 재시작 후 이어받기 |
| 자동 확인 | 10분~7일 간격, FF 재시작 시 스케줄 등록 |
| 중복 방지 | 작품 ID + 회차 ID, 완료 파일 SHA-256 확인 |
| 동시 실행 방지 | 스레드 및 FF 프로세스 간 파일 잠금 |
| 저장 | UTF-8 TXT, 작품별 텍스트 합본 EPUB 3, info.json |
| 이력 | 최근 300개 회차, 최근 100개 로그 표시, 최대 3,000개 로그 보관 |
| 시간 | Asia/Seoul 기준 표시 및 +09:00 저장 |
| 로그인 정보 | 별도 0600 쿠키 파일, 화면 재노출/원문 응답 로깅 없음 |

저장 예:
```text
저장폴더/작품명 [작품번호]/
  info.json
  00100_회차 제목 [회차ID].txt
  작품명.epub
```

합본 EPUB은 해당 작품의 검증된 완료 TXT 전체를 묶습니다. 시작 범위를 나중에 바꿔도 이미 받은 TXT가 합본에서 제거되지는 않습니다.
작품 등록 해제 시에도 파일과 이력은 유지합니다. 제목이 바뀌어도 기존 작품 폴더를 유지합니다.
저장 루트를 변경하면 기존 파일을 자동 이동하지 않습니다. 기존 파일이 남아 있으면 완료로 인식하며, 새 회차는 새 루트에 저장합니다.

## 현재 범위와 알려진 제한

- **TXT와 텍스트 EPUB** 중심입니다. 삽화는 `[삽화]` 위치 표시만 저장하고 이미지 자체는 저장하지 않습니다.
- 작품명 검색/연재 목록 탐색, 표지 수집, Telegram/Discord 알림은 이번 버전에 포함하지 않았습니다.
- 이미지 전용 또는 암호화된 소설 뷰어는 지원하지 않습니다. 지원하지 않는 형식을 억지로 변환하지 않습니다.
- 기다무 판단은 보수적으로 동작합니다. 카카오가 일반 대여권을 추천해 `RT05` 대신 다른 유형을 반환하면,
  실제로 기다무 사용이 가능한 작품이라도 **기다무 확인 필요**로 멈출 수 있습니다. 이때 비밀값 없는 응답 구조 확인이 필요합니다.
- 새 회차 삽입으로 순번이 달라져도 기존 TXT 이름을 자동 재정렬하지 않습니다. EPUB 목차는 재확인된 목록 순번을 사용합니다.
- 실제 카카오 로그인/기다무 사용/FF 스케줄 연동은 설치 후 테스트가 필요합니다. 테스트 통과는 실서비스 동작 보장을 뜻하지 않습니다.

오류 보고 시 화면에 나온 오류 코드, FF 버전, 플러그인 버전, 작품 번호만 알려주세요.
쿠키·대여 확인값·서명 URL·본문은 GitHub 이슈나 공개 로그에 올리지 마세요.

## 개발 테스트

저장소의 상위 디렉터리에서 실행:
```sh
python -m pip install -r kakao_novel_downloader/requirements-dev.txt
python -m unittest discover -s kakao_novel_downloader/tests -v
```
테스트는 모의 서버 응답과 임시 디렉터리만 사용하며 실제 계정이나 대여권을 사용하지 않습니다.
템플릿 JavaScript 문법 검사에는 Node.js가 필요합니다. FF 설치 시에는 Node.js가 필요하지 않습니다.

### v0.1.2 수정

대여 후 `open_page` 응답 형식만 확인되지 않을 때 본문 API로 실제 접근권을 확인합니다. 인증 실패와 명시적인 거부는 중단합니다. API 응답 오류에는 요청 경로를 표시합니다. 기존 대여 기록은 유지하며 동일 회차에 이용권을 다시 사용하지 않습니다. FF 플러그인 업데이트 후 FF를 재시작하고 작품에서 지금 실행을 누르세요.
